# AI 生成代码信号清单

本文件是主观信号评估的完整检查表。与 `scripts/analyze_repo.py` 输出的客观指标配合使用：
**客观指标给证据，主观信号给判断**，两者综合后按"置信度规则"给结论。

## 1. 代码层面信号

| 信号 | AI 生成的典型特征 | 真人编写的典型特征 |
| --- | --- | --- |
| 变量/函数命名 | 教科书式规范（`calculateTotalAmount`、`getUserById`）或过度泛化（`data`/`item`/`result`/`temp`/`obj`） | 有个人习惯：领域缩写、历史遗留命名、有趣的命名（`hog`、`lastChance`） |
| 注释 | 像讲课/文档："// 创建一个列表存储用户数据"；每行解释"是什么" | 只解释"为什么"和"坑"；语气像聊天；有 TODO 个人风格 |
| 结构 | 过于工整：一个函数只做一件事、参数类型齐全、无一处偷懒 | 有现实痕迹：硬编码、magic number、特殊场景分支、偶尔的捷径 |
| 错误处理 | 规整地 catch 所有异常 + 统一打日志 | 针对特定错误做特定处理；有时故意忽略某些异常 |
| 防御式编程 | 到处判空（`if x != null` 层层嵌套）或完全不防御 | 在真实出过 bug 的地方防御，其他地方不防 |
| 泛化程度 | 代码"通用性过强"，无特定环境/业务痕迹 | 有特定环境的适配：路径、端口、方言、兼容性 hack |
| 死代码 | stub 函数（pass/return null）、未用 import、占位 return、紧邻重赋值、整段注释掉的旧代码 | 有删改痕迹：删过函数、重构后清理、废弃分支被移除 |
| 语言习惯 | 无个人色彩；中英混排注释；语气一致到没有起伏 | 有口头禅、缩写风格、个人注释签名 |

## 2. 工程层面信号（通常比代码本身更硬）

- **Git 历史**：真人项目有渐进式提交（`fix:`、`revert`、`wip`、深夜提交、多次小提交）；AI 生成常为单次大提交、一次成型、信息规整无演进。
- **版本迭代**：真人有 v1 遗骸、废弃代码、重构痕迹；AI 一上来就是"最终版"，干净得可疑。
- **调试残留**：真人留 `console.log` / `print` / `Debug.WriteLine` / 注释掉的旧代码；AI 写得很干净。**注意**：完全无残留 + 注释完美，本身也是可疑信号。
- **环境适配**：真人有针对特定系统/机器的硬编码与兼容分支；AI 代码与环境无关。
- **测试风格**：真人的测试有业务场景、边界值、踩坑记录；AI 的测试覆盖"教科书样例"。

## 3. 验证手段（可操作步骤）

1. **git log 检查**（最硬证据）：`git log --oneline` 看提交次数、信息风格、时间跨度；`git shortlog -sn` 看作者数；检查是否有渐进式开发。
2. **问作者细节**：挑一段非显而易见代码问"为什么这么写"。AI 代码的署名作者通常答不出深层原因。
3. **反编译二进制**：`.exe`/`.apk` 用反编译工具看字符串与日志语气——AI 生成的错误消息往往"礼貌且正式"，真人有口语化甚至粗鲁日志。
4. **AI 检测器（GPTZero 等）**：只能当参考，误报率高，不作为结论依据。
5. **与已知事实对照**：代码声称支持的平台/API 是否与作者描述一致；AI 常"自信地写错"（幻觉 API、错误版本）。

## 4. 常见误判（务必检查）

- **AI 生成 + 真人修改几笔**：特征被冲淡，通常无法可靠识别——如实报告"无法判定"。
- **小项目（几千行内）**：特征弱，倾向"证据不足"而非强结论。
- **真人但风格规范**（如严格 lint、团队规范、文档驱动开发）：可能误判为 AI——用工程痕迹（git 演进）纠正。
- **代码生成器/脚手架产物**（IDE 模板、框架生成）：特征像 AI 但来源不同，先排除。
- **学习者/新手代码**：注释多、命名泛化，容易被误判为 AI——结合逻辑深度判断。

## 5. 置信度规则

| 证据组合 | 结论 |
| --- | --- |
| ≥3 个代码层面信号 + 工程痕迹缺失（无演进、无残留、一次成型） | **高概率 AI 生成** |
| 2-3 个代码信号，无工程痕迹可查 | **倾向 AI（中等置信）** |
| 信号混杂、正反都有 | **无法判定**，列出证据让用户自己判断 |
| 有明显真人痕迹（渐进 git 历史、个人命名、踩坑注释、环境 hack） | **倾向真人（中等置信）** |
| git 演进充分 + 个人风格明显 + 调试残留自然 | **高概率真人编写** |

**永远要输出证据列表，不输出裸结论**——让用户能自己复核每一条。
